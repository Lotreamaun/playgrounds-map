## 1. Технологии

### Frontend
- **React 18 + TypeScript** — UI и типизация
- **Vite** — сборка и dev-сервер
- **react-leaflet + Leaflet** — карта и маркеры площадок
- **OpenStreetMap** — бесплатные тайлы карты
- **vite-plugin-pwa** — service worker, манифест, офлайн-режим

### Backend
- **Python 3.12+** — основной язык
- **FastAPI** — асинхронный веб-фреймворк, автогенерация OpenAPI-схемы
- **SQLAlchemy 2.0 (async)** — ORM
- **SQLite** — основная БД на MVP-этапе
- **Pydantic** — валидация данных

### Дополнительно
- **python-dotenv** — переменные окружения
- **Docker + Docker Compose** — контейнеризация и деплой
- **Dockhost** — целевая платформа деплоя

## 2. Принципы разработки

### Архитектурные принципы
- **Модульность** — разделение на логические модули
- **Простота** — приоритет читаемости кода
- **DRY** — избегание дублирования кода
- **Single Responsibility** — каждый модуль отвечает за одну задачу
- **KISS** – Keep It Simple, Stupid
- **Итеративная разработка** - маленькими шагами с быстрой обратной связью

### Принципы кодирования
- **Type hints / TypeScript** — типизация на обоих слоях
- **Документирование** — docstrings и комментарии для нетривиальной логики
- **PEP 8 / ESLint** — стандартный стиль кода
- **Конфигурация через переменные окружения**

### Принципы работы с данными
- **Idempotency** — повторная отправка формы не создаёт дубликат площадки (проверка по координатам/названию)
- **Persistence** — все данные о площадках хранятся в SQLite, без пересбора при каждом запуске
- **Async everywhere** — FastAPI + SQLAlchemy async, чтобы API не блокировался на I/O

### Принципы работы с картой
- **Canvas-рендеринг** (`preferCanvas: true`) — маркеры рисуются на Canvas, а не как DOM-узлы, для производительности
- **Кластеризация** — группировка близких точек через Leaflet.markercluster при увеличении количества площадок
- **Graceful degradation** — если геолокация пользователя недоступна, карта открывается с дефолтным центром города

## 4. Архитектура проекта

```
Пользователь → [React PWA + Leaflet карта] → [FastAPI backend] → [SQLite]
                                                    ↓
                                    [Сервисы: валидация, поиск площадок]
```

### Компоненты и их взаимодействие

1. **frontend/src/App.tsx** — точка входа UI
   - Рендер карты и общего layout
   - Управление состоянием выбранной площадки

2. **frontend/src/components/MapView.tsx** — карта
   - Инициализация Leaflet, центрирование по геолокации
   - Отображение маркеров площадок, кластеризация

3. **frontend/src/components/CourtForm.tsx** — добавление площадки
   - Форма: координаты (клик на карте), покрытие, состояние, фото
   - Отправка данных на backend

4. **backend/app/main.py** — точка входа API
   - Инициализация FastAPI, подключение роутеров
   - CORS-настройки для фронтенда

5. **backend/app/routers/courts.py** — HTTP-интерфейс
   - `GET /courts` — список площадок (с фильтром по bounding box)
   - `POST /courts` — добавление новой площадки
   - `GET /courts/{id}` — детали площадки

6. **backend/app/services/court_service.py** — бизнес-логика
   - Валидация координат и обязательных полей
   - Проверка на дублирование (по близким координатам)

7. **backend/app/models/court.py** — модель данных
   - Описание таблицы `courts` в SQLAlchemy

## 5. Модель данных

### Основные сущности

**Courts (Площадки)**
```sql
courts:
- id (Integer, Primary Key)
- sport_type (String) — вид спорта: basketball, football, volleyball, tennis, hockey
- name (String, Nullable) — название/ориентир (например, "площадка у школы №5")
- latitude (Float)
- longitude (Float)
- surface (String) — покрытие: asphalt, rubber, grass, sand, wood, other
- condition (String) — состояние: excellent, good, fair, poor
- has_lighting (Boolean) — освещение
- description (Text, Nullable) — свободный комментарий пользователя
- photo_url (String, Nullable)
- created_at (Timestamp)
- updated_at (Timestamp)
```

## 6. Сценарий работы (MVP)

1. Пользователь открывает карту, видит своё местоположение и площадки рядом
2. Пользователь кликает на маркер — открывается карточка с деталями площадки
3. Пользователь кликает "Добавить площадку" → указывает точку на карте → заполняет форму (покрытие, состояние, фото)
4. Backend валидирует и сохраняет площадку в SQLite
5. Новая площадка сразу появляется на карте у всех пользователей

## 7. Деплой
