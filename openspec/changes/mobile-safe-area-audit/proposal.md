## Why

Дизайн-система (`docs/courtmap-design-system.md` §10) фиксирует конкретные технические детали мобильного layout: `100svh` вместо `100dvh` для стабильных контейнеров (карта, корневой layout) — чтобы не дёргаться при каждом скролле/сворачивании адресной строки браузера; буфер поверх `env(safe-area-inset-bottom)` для плавающих элементов внизу экрана, так как сам `env()` не отражает раскрытое/свёрнутое состояние панели браузера; `interactive-widget=resizes-content` в viewport meta для устойчивого поведения при фокусе на инпуте в развёрнутой форме. Аудит текущего кода показал, что часть этого уже реализовано правильно (`.bottom-sheet__content`, `.bottom-sheet--modal` на `100dvh` — это осознанное исключение для формы, а не баг), но мобильный `@media`-блок в `index.css` **переопределяет** `#root`/`.map-view` с `100svh` (уже верно заданных в базовых правилах) обратно на `100dvh` — то есть именно на мобильном, где нестабильность высоты заметнее всего, применяется противоположное дизайн-системе поведение. Плюс у `.fab` не хватает буфера сверх `env()`, а viewport meta не содержит `interactive-widget=resizes-content`.

## What Changes

- Убрать переопределение `#root`/`.map-view` на `100dvh` внутри мобильного `@media`-блока — оба контейнера остаются на `100svh` на всех брейкпоинтах (стабильный размер, не пересчитывается при скролле/схлопывании панели браузера).
- `.fab`: `bottom` получает дополнительный буфер сверх `env(safe-area-inset-bottom)` (`+ 24px + 16px` вместо текущих `+ 24px`), чтобы не упираться в собственную (несхлопнутую) панель браузера, которую `env()` не учитывает.
- Добавить `interactive-widget=resizes-content` в `<meta name="viewport">` (`frontend/index.html`) — для корректного поведения при фокусе на инпуте (адрес) в развёрнутой полноэкранной форме на мобильном.
- **Без изменений (уже корректно, проверено аудитом):** `.bottom-sheet__content` padding-buffer уже соответствует дизайн-системе; `.bottom-sheet--modal` на `100dvh` — намеренное исключение (форма должна пересчитываться под клавиатуру), не трогается; в коде нет постоянно докнутого нижнего бара (FAB — плавающий, не полноширинный) — принцип §10 уже не нарушается, отдельных изменений не требует.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `frontend-mapping`: добавляется требование стабильности размера карты — контейнер карты не пересчитывает высоту при каждом скролле/схлопывании панели браузера на мобильном.
- `frontend-bottom-sheet`: плавающие элементы у нижнего края экрана (FAB) учитывают буфер сверх safe-area-inset, а не только сам inset; полноэкранная форма-модалка корректно пересчитывается под появление экранной клавиатуры.

## Impact

Frontend only, небольшой diff: `frontend/src/index.css` (удаление dvh-переопределения в мобильном media-блоке, буфер `.fab`), `frontend/index.html` (viewport meta). Изменений `.tsx`, backend/API нет.
