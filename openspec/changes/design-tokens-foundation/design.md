## Context

`frontend/src/index.css` уже определяет CSS custom properties (`--text`, `--text-h`, `--bg`, `--border`, `--accent`, `--accent-bg`, `--accent-border`, `--shadow`, `--sans`, `--heading`, `--mono`) в блоке `:root` и переопределяет часть из них в `@media (prefers-color-scheme: dark)`. Это дефолтная тема Vite-скаффолда, не приведённая к продукту. Проверено: ни один `.tsx`/`.ts`-файл не обращается к этим переменным напрямую (`grep -rn "var(--" frontend/src --include="*.tsx" --include="*.ts"` — пусто) — все обращения живут внутри самого `index.css` (47 использований на 7 токенов). Значит правки внутри `index.css` не требуют правок компонентов. См. `proposal.md` — «Why» за мотивацией и `docs/courtmap-design-system.md` за полным перечнем токенов.

## Goals / Non-Goals

**Goals:**
- Завести полный набор токенов дизайн-системы (шрифт, цвет, spacing/radius/motion, элевация, `.glass-over-map`) в `index.css`.
- Перекрасить существующую палитру (`--bg`, `--border`, `--text`, `--text-h`, `--accent`) в значения дизайн-системы, не трогая ни одного `.tsx`.
- Дать последующим change'ям («map-chrome-and-markers», «surface-components-restyle», «mobile-safe-area-audit») стабильный, канонический набор имён токенов, на который они будут переключать конкретные компоненты.

**Non-Goals:**
- Применение новых токенов к конкретным компонентам/маркерам/панелям — это последующие change'и.
- Ручной переключатель темы (light/dark toggle UI) — не строится в этом change; только техническая готовность токенов под него (см. «Decisions» → data-theme).
- Миграция/удаление легаси-имён `--accent-border`, `--shadow` — помечено как follow-up, не блокирует этот change.

## Decisions

### 1. Существующие имена токенов не переименовываются — переопределяются их значения

Поскольку все 47 использований `var(--text)`, `var(--text-h)`, `var(--bg)`, `var(--border)`, `var(--accent)`, `var(--shadow)` живут внутри `index.css`, теоретически можно было бы сделать чистый rename на канонические имена дизайн-системы (`--text-primary`, `--text-secondary`, `--surface`, …) одним проходом по файлу. Выбран более консервативный путь: **имена токенов остаются прежними, меняются только их значения** на палитру дизайн-системы:
- `--bg` → `#FAFAFA` / тёмная `#121214` (страница-канва)
- `--border` → `#E4E4E7` / тёмная `#2C2C30`
- `--text-h` → `#18181B` / тёмная `#F4F4F5` (уже семантически ближе всего к «primary text»)
- `--text` → `#71717A` / тёмная `#9A9AA0` (уже семантически ближе всего к «secondary text»)
- `--accent` → `#2A2D34` / тёмная `#E4E4E7` (графит, инверсия в тёмной теме)

Альтернатива (полный rename) отклонена: она раздувает диff этого change правками во всех 47 местах без изменения наблюдаемого поведения ни в одном из них — чистый риск конфликтов при последующих change'ях, которые и так будут переоткрывать эти строки. Вместо этого канонические имена дизайн-системы заводятся как **новые токены**, часть из которых — тонкие алиасы к уже существующим:

```css
--text-primary: var(--text-h);
--text-secondary: var(--text);
```

`--surface` — не алиас, а полноценный новый токен (`#FFFFFF` / тёмная `#1B1B1E`): раньше отдельного «поверхностного» слоя не было, карточки/панели неявно опирались на `--bg`, поэтому здесь нет существующего значения для переиспользования.

`--accent-bg` и `--accent-border` (7 использований суммарно) остаются как есть по имени, но получают новые значения: `--accent-bg` продолжает играть роль альфа-подложки под accent (переиспользуется как основа для `--accent-focus: var(--accent-bg)`), `--accent-border` перестаёт быть полупрозрачным фиолетовым и указывает на сплошной `var(--accent)`. Ни один из 7 call site'ов не редактируется.

### 2. Тема: поддержать и `prefers-color-scheme`, и `[data-theme]` одновременно

`courtmap-design-system.md` §2.1 определяет тёмную тему через селектор `[data-theme="dark"]`, подразумевая будущий ручной переключатель темы, которого пока нет в проекте (сейчас тема переключается только через `@media (prefers-color-scheme: dark)`). Чтобы не переписывать токены второй раз, когда переключатель появится, тёмный блок дублируется под оба селектора сразу:

```css
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { /* тёмные значения */ } }
[data-theme="dark"] { /* те же тёмные значения */ }
```

Без переключателя UI `[data-theme]` на `<html>`/`<body>` никогда не проставляется, так что это чистое дополнение — поведение по `prefers-color-scheme` не меняется.

### 3. `.glass-over-map` и `prefers-reduced-transparency`

Реализуется как переиспользуемый класс с `backdrop-filter: blur(14px)` (+ `-webkit-` префикс) поверх полупрозрачной графитовой заливки, по спецификации §3 дизайн-системы. `prefers-reduced-transparency` — медиа-фича с ограниченной поддержкой браузеров (нет в части версий Firefox/Safari на момент написания); там, где она не поддерживается, элемент просто остаётся полупрозрачным (деградация не ломает функциональность, только снижает доступность до появления ручного тоггла — см. Non-Goals). Фолбэк подключается декларативно через `@media (prefers-reduced-transparency: reduce)`, без JS-детекта.

### 4. Уровни тени — новые токены, `--shadow` не трогаем

Вместо переименования существующего `--shadow` (12 использований) в новые токены элевации, заводятся отдельные `--shadow-1`/`--shadow-2`/`--shadow-3` по уровням §3 дизайн-системы. `--shadow` остаётся как есть — его 12 текущих call site'ов не входят в область этого change.

### 5. Шрифт через `@import` в CSS, не через `<link>` в `index.html`

`index.css` уже подключает `@yandex/ymaps3-default-ui-theme` через `@import` в начале файла — Google Fonts-шрифт Commissioner добавляется тем же способом сразу после, для единообразия точки подключения внешних стилей.

## Risks / Trade-offs

- **[Риск] Тонкие алиасы (`--text-primary: var(--text-h)`) создают два имени на одну роль** → Осознанный компромисс ради нулевого диффа в существующих 47 call site'ах; последующие changes, трогающие конкретные компоненты, могут постепенно переключать их на канонические имена по месту (не блокирует этот change).
- **[Риск] `prefers-reduced-transparency` не работает во всех браузерах** → Деградация graceful (остаётся прозрачным), не блокер; ручной тоггл — future work, зафиксировано в Non-Goals.
- **[Риск] Переопределение `--bg`/`--border`/`--text`/`--accent` по значению сразу перекрашивает весь текущий UI** (это ожидаемо и является целью change'а), но делает диff визуально заметным даже там, где конкретный компонент ещё не адаптирован под новую дизайн-систему по разметке/spacing — временно возможны места с новым цветом, но старыми отступами/тенями, пока не пройдут последующие changes. Это ожидаемый переходный период, а не баг.

## Open Questions

- Когда добавится ручной переключатель темы (не в этом change), нужно решить, ставится ли `data-theme` на `<html>` или `<body>`, и как это согласуется с уже заложенным `:root:not([data-theme="light"])` в п. 2 — не блокирует текущие спеки/задачи.
