## Context

Текущий фронтенд (React 19 + Vite + ymaps3, без UI-библиотек и без тестов) устроен так:

- `App.tsx` держит всё состояние: режимы, шторки, геолокацию для формы.
- `MapView.tsx` сам грузит площадки по bbox при каждом `onUpdate` и сам запрашивает геолокацию. Параллельно `App` грузит все площадки для списка, а `CourtList` делает свой запрос геолокации.
- Контролы карты встроены через `YMapControls`/`YMapControl` и сдвигаются CSS-хаком по классу `.ymaps3--controls_vertical`.
- `BottomSheet` один на все случаи: модальный overlay, peek/expanded, drag.
- `CourtCard` живёт в `CourtMarker.tsx`.
- `index.css` (1000+ строк) содержит наследие Vite-шаблона (`#social`, `.counter`, `h1 56px`), неиспользуемые `.toggle` и `.glass-over-map`.

Мотивация и список проблем — в `proposal.md`, требования — в `specs/`.

## Goals / Non-Goals

**Goals:**
- Главный сценарий за ≤ 3 действия: поиск или маркер → карточка → «Маршрут»/«Скопировать адрес».
- Один источник данных площадок и один источник геолокации на всё приложение.
- Нейтральный визуальный язык без стекла, который легко поддерживать в двух темах.
- Не ухудшить метрики загрузки: бандл JS не растёт больше чем на ~10 КБ gzip (без учёта шрифта); отсутствуют render-blocking внешние запросы. После доработок раздела 11 (фильтры, факты, фото) бюджет — не больше 95 КБ gzip всего JS.

**Non-Goals:**
- Роутер и многостраничность. Состояние UI живёт в `App`, в URL только `?court=<id>`.
- UI-kit/CSS-фреймворк (Tailwind, MUI и т.п.) и CSS-модули. Остаётся один `index.css`, но перестроенный по секциям.
- Тестовая инфраструктура: тестов в проекте нет, проверка — ручная по сценариям спеков в браузере (desktop + мобильная эмуляция, обе темы).
- Изменения backend.

## Decisions

### 1. Нейтральный стиль вместо гибрида Material × Liquid Glass
Все поверхности непрозрачные, иерархия задаётся тенью и границей. Анимации только `transform`/`opacity`, одна кривая `ease-out`, длительности 150/250 мс. Спека `material-liquid-glass-spec.md` и UI-kit уходят в `docs/archive/`, `courtmap-design-system.md` переписывается.
*Альтернатива:* довести гибрид по спеке (luminance sampling, overlap-детектор, freeze-frame блюра). Отклонено: много кода ради эффекта, который на карте ухудшает читаемость и FPS на слабых Android.

### 2. Состояние приложения: один дискриминированный `ui`-стейт + два хука данных
- `useCourts()` — модульный кэш:
  - один `getCourts()` без bbox на сессию;
  - состояния `loading | ready | error`;
  - `retry()`;
  - `add(court)` для оптимистичного добавления после `POST`.
- `useGeolocation()` — модульный стор на `useSyncExternalStore`:
  - `status: idle | locating | ready | denied | unavailable`;
  - `position`;
  - `request()`;
  - автозапрос один раз при старте;
  - повторный `request()` только по явному действию;
  - конкурентные вызовы склеиваются в один промис.
- `App` хранит `ui: { kind: 'browse' } | { kind: 'search' } | { kind: 'card', courtId } | { kind: 'form', ... }`. Мобильный и desktop рендерят разные оболочки над одними и теми же состоянием и компонентами.

*Почему модульный стор, а не Context:* приложению нужен один экземпляр, а провайдер и ре-рендер всего дерева не нужны. *Альтернатива:* zustand/redux. Отклонено как лишняя зависимость.

### 3. Все площадки одним запросом, без bbox-перезапросов
MVP — один город, порядок сотен площадок; ответ — десятки КБ. Кластеризация `@yandex/ymaps3-clusterer` уже справляется с рендером. Это убирает гонки ответов при движении карты и двойную загрузку. `getCourts(bbox)` в клиенте остаётся для будущего.
*Порог пересмотра:* ~2000 площадок или ответ > 300 КБ. Тогда вернуть bbox и серверный поиск.

### 4. Поиск на клиенте
Нормализация: `toLowerCase()`, замена `ё→е`. Поиск по `name` и `address` через `includes`. Ввод пропускается через `useDeferredValue`, чтобы не тормозить набор. Расстояния считаются один раз на пару (`courts`, `position`) через `useMemo` и переиспользуются списком и карточкой. Сортировка: по расстоянию, если `position` есть, иначе по `name` через `localeCompare('ru')`.

### 5. Мобильные оболочки: `CardSheet` и `FullScreenLayer` вместо универсального `BottomSheet`
- `CardSheet` — немодальная шторка:
  - без overlay-элемента, поэтому события доходят до карты за пределами шторки;
  - высота `auto`, `max-height: 85dvh`, прокрутка внутри;
  - drag вниз за ручку или шапку: порог 80 px или скорость, иначе возврат;
  - кнопка «×», Escape.
- `FullScreenLayer` — для экрана поиска и формы:
  - `position: fixed; inset: 0`, без анимации высоты;
  - `100dvh` (сохраняется исключение из `mobile-safe-area-audit` для клавиатуры).
- Карта при этом **не размонтируется**: слои лежат поверх неё. Так сохраняются положение и тайлы.
- Открытие `FullScreenLayer` на мобильном добавляет запись в history (`pushState({ layer })`), а `popstate` закрывает слой. Так системная кнопка «назад» на Android закрывает поиск, а не уходит со страницы. `?court` при этом обновляется только через `replaceState`.

### 6. Собственные DOM-контролы карты вместо `YMapControls`
`MapControls` — абсолютно позиционированный стек внутри `.map-view`, у правого края:
- `bottom: calc(env(safe-area-inset-bottom) + 64px)` на мобильном;
- `bottom: 48px` на desktop (над строкой атрибуции Яндекса).

Кнопки вызывают методы инстанса карты через ref (`setLocation`, `zoom`).
*Почему:* полный контроль над позицией, скрытием при открытой шторке и ARIA без CSS-хаков по внутренним классам ymaps. Удаляются `YMapControls`/`YMapControl` из `yandexMaps.ts` и хак `.ymaps3--controls_vertical`.
*Альтернатива:* оставить `YMapControls position="bottom right"` и подбирать margin. Отклонено: позиция атрибуции и наших слоёв всё равно требует ручной синхронизации.

### 7. Центрирование площадки с учётом шторки
При выборе площадки на мобильном карта центрируется так, чтобы маркер оказался в видимой части над шторкой. Для этого используется проп `margin` у `YMap` (`[top, right, bottom, left]`, учитывается при `setLocation`). `bottom` = текущая высота шторки, которая измеряется `ResizeObserver`. На desktop `margin` = 0: панель не перекрывает карту.
*Фолбэк:* если `margin` не влияет на центрирование в используемой версии ymaps3, сдвинуть `center` на `sheetHeight/2` пикселей через перевод px→градусы на текущем зуме.

### 8. Маршрут: меню ссылок, без SDK
URL-шаблоны:
- Google: `https://www.google.com/maps/dir/?api=1&destination={lat},{lon}`
- Яндекс: `https://yandex.ru/maps/?rtext=~{lat},{lon}&rtt=auto`
- Apple: `https://maps.apple.com/?daddr={lat},{lon}`

Apple-устройство определяется по `/iPhone|iPad|iPod|Macintosh/.test(navigator.userAgent)`. `Macintosh` покрывает и Mac, и iPadOS, который маскируется под Mac; Apple Maps есть на обоих. Ссылки `target="_blank" rel="noopener"`; на телефонах universal links открывают приложение.

Меню (`RouteMenu`) — кнопка с `aria-expanded` и список ссылок под ней, внутри карточки. Не отдельный попап с порталом: так меньше проблем с позиционированием в шторке.
- В мобильной шторке список встраивается в поток под кнопкой, шторка растёт.
- В боковой панели desktop список выпадает поверх блока фактов (`position: absolute` внутри карточки).

Референс — мокапы `docs/mockups/neutral-map-ui.html`.

### 8a. «Поделиться» и «Сообщить о проблеме»
- **«Поделиться»:**
  - если есть `navigator.share`, вызываем `navigator.share({ title: name, url })`;
  - `AbortError` (пользователь закрыл системное меню) игнорируем;
  - без `navigator.share` копируем `url` через тот же механизм, что и адрес (решение 9), с тостом «Ссылка скопирована»;
  - `url = location.origin + '/?court=' + id`.
- **«Сообщить о проблеме»:**
  - адрес берётся из `import.meta.env.VITE_REPORT_URL`, подстрока `{id}` заменяется на id площадки (`encodeURIComponent`);
  - пустая переменная — ссылка не рендерится;
  - канал может быть любым: Telegram-бот (`https://t.me/<bot>?start=court_{id}`), Google-форма с предзаполненным полем, `mailto:`.

  *Почему env, а не хардкод:* канал ещё не выбран, а смена канала не должна требовать правки кода.

### 8b. Фото, описание, дата в карточке
- `CourtCard` получает проп `layout: 'panel' | 'sheet'`:
  - `panel` — фото во всю ширину сверху;
  - `sheet` — миниатюра 88×88 (`object-fit: cover`, радиус 12) в одной строке с блоком «спорт / название / расстояние».

  Лайтбокс общий.
- Описание выводится с `white-space: pre-line`, без обрезки: шторка и так прокручивается внутри.
- Дата форматируется через `new Intl.DateTimeFormat('ru', { day: 'numeric', month: 'long', year: 'numeric' })`. Редактирования площадок пока нет, поэтому `updated_at` совпадает с датой добавления; формулировка «Данные от» верна в обоих случаях.

### 8c. После добавления площадки
`handleCreated`:
1. `useCourts().add(court)`;
2. закрыть форму;
3. `ui = { kind: 'card', courtId: court.id }`;
4. тост «Площадка добавлена».

Центрирование и `?court` срабатывают через обычный путь выбора площадки (решения 7, 10).

### 9. Копирование и тост
`navigator.clipboard.writeText`. При ошибке или отсутствии API — тост «Не удалось скопировать». Один `Toast` на приложение: `role="status"`, `aria-live="polite"`, автоскрытие через 2 с, лежит над шторкой.

### 10. Deep link `?court=<id>`
- На старте `id` читается из `URLSearchParams`.
- Когда `useCourts` перешёл в `ready`, площадка ищется в данных. Найдена — открывается карточка и карта центрируется. Не найдена — параметр удаляется через `replaceState`.
- Выбор и закрытие карточки обновляют параметр через `replaceState`.

### 11. Шрифт: `@fontsource-variable/commissioner`
Импорт `@fontsource-variable/commissioner/wght.css` в `main.tsx`. Пакет кладёт woff2 в бандл с хешами и `unicode-range`-сабсетами: браузер грузит только кириллицу/латиницу. `font-display: swap` задан пакетом. Семейство — `'Commissioner Variable'`, далее системный стек. `@import` Google Fonts удаляется. Preload не делаем: имена файлов хешируются, а swap даёт мгновенный текст.
*Альтернатива:* вручную скачать woff2 в `public/`. Отклонено: ручное обновление и риск забыть `unicode-range`.

### 12. Токены и тёмная тема
Роли:
- `--bg`, `--surface`, `--surface-2` (фон чипов и hover);
- `--border`;
- `--text-primary`, `--text-secondary`;
- `--accent`, `--accent-hover`, `--accent-focus`, `--text-on-accent`;
- `--sport-*`, `--feedback-error*`;
- шкалы `--space-*`, `--radius-*`, `--shadow-1..3`, `--dur-fast/base`, `--ease-out`.

Тёмная тема определяется один раз через `@media (prefers-color-scheme: dark)` на `:root`. Блок `[data-theme]` удаляется: переключателя темы нет. Старые алиасы (`--text`, `--text-h`, `--social-bg`, `--code-bg`, `--accent-bg`, `--accent-border`) удаляются вместе с использованиями. `.btn-primary` использует `color: var(--text-on-accent)`.

### 13. Раскладка desktop
Панель 380 px слева:
- шапка: «CourtMap» и маленькая secondary-кнопка «+ Добавить», под ними поле поиска;
- контент: список / карточка с «← К списку» / форма.

Позиция прокрутки списка и запрос поиска хранятся в `App` (`searchQuery`) и `ref` на контейнере прокрутки. Список не размонтируется при показе карточки, а скрывается через `hidden`, поэтому прокрутка сохраняется бесплатно.

### 14. Производительность рендера карты
- `clusterByGrid({ gridSize: 64 })` и колбэки `renderMarker`/`renderCluster` мемоизируются.
- `CourtMarker` оборачивается в `React.memo` с пропами-примитивами (`id`, `sportType`, `selected`, `name`), чтобы выбор одной площадки не перерисовывал все маркеры.
- Фото: `loading="lazy"`, `decoding="async"`, `aspect-ratio: 16/9` и фон-плейсхолдер.

### 15. Ошибка загрузки карты и повтор
- Если скрипт ymaps3 не загрузился или `ymaps3.ready` упал, вместо карты показывается состояние ошибки:
  - заголовок «Карта не загрузилась»;
  - подсказка «Проверьте интернет и попробуйте ещё раз»;
  - кнопка «Повторить».

  Технические подробности идут только в `console.error`.
- Сообщение о пустом `VITE_YANDEX_MAPS_KEY` остаётся как есть: оно для разработчика.
- `loadScript` при ошибке удаляет свой элемент `<script id="yandex-maps-js-api">`. Иначе повторный вызов увидит старый тег, сразу вернёт `resolve()` и упадёт на неопределённом `ymaps3`.
- Поле поиска, список и карточки работают и без карты. Стек контролов (включая «+») не показывается: без карты нельзя выбрать точку.
- Причина, найденная на iPhone, — ограничение ключа по HTTP Referer (страница открыта по IP). Это не баг кода; адрес добавляет в кабинете Яндекса владелец ключа.

### 16. Поля ввода не вызывают авто-зум iOS
Safari на iOS увеличивает страницу при фокусе на поле со шрифтом меньше 16 px. Все `input`, `textarea` и `select` получают `font-size: 16px` (токен `--text-input`). `maximum-scale=1` и `user-scalable=no` во viewport не используются: они запрещают пользователю масштабировать страницу.

### 17. Высота поля поиска во всех контекстах
У базового `.search-field` убирается `flex: 1`. Растягивание по ширине задаётся там, где поле стоит в строке: шапка экрана поиска и плавающее поле на мобильной карте. В колонке шапки боковой панели поле получает свою высоту 44 px. Проверить все три места.

### 18. Фото площадки: один компонент `CourtPhoto`
- Пропсы:
  - `src: string | null`;
  - `sportType`;
  - `variant: 'thumb' | 'sheet' | 'banner'`. Размеры: `thumb` — 56×56 в списке, `sheet` — 88×88 в мобильной карточке, `banner` — во всю ширину desktop-карточки, `aspect-ratio: 16/9`.
- **Заглушка** (нет фото или ошибка загрузки):
  - фон — `color-mix(in srgb, var(--sport-<type>) 14%, var(--surface-2))`;
  - по центру иконка спорта цветом `--sport-<type>`, примерно 45% размера;
  - у `banner` заглушка ниже фото — 120 px — и с подписью «Фото пока нет», чтобы не тратить пол-экрана на пустоту.
- **Фото:**
  - `loading="lazy"` и `decoding="async"`;
  - лежит поверх заглушки с `opacity: 0` и проявляется до 1 по `onLoad` за `--dur-base`; при `prefers-reduced-motion` — без перехода;
  - при `onError` остаётся заглушка.
- Миниатюра в списке декоративная (`alt=""`): название уже есть в строке. В карточке фото — кнопка открытия лайтбокса. Заглушка не интерактивна.
- Фото на сервере не уменьшаются (до 5 МБ). Поэтому форма перед отправкой сжимает фото на клиенте: длинная сторона ≤ 1600 px, JPEG с качеством 0,8, через `createImageBitmap` + `canvas`; при неудаче отправляется оригинал. Серверные превью — вне скоупа.

### 19. Визуальные факты: `CourtFacts` и `SportBadge`
- `CourtFacts` — ряд чипов в фиксированном порядке «Покрытие · Состояние · Свет», с вариантами `compact` (список, высота 24, шрифт 13) и `regular` (карточка, высота 32, шрифт 14). Чип = маркер + слово, фон `--surface-2`, радиус полный, без переноса внутри чипа.
  - **Покрытие:** квадрат 10×10 с радиусом 3 цветом `--material-<surface>`. Цвета: асфальт — тёмно-серый, резина — терракота, трава — зелёный, песок — песочный, дерево — коричневый, другое — нейтральный с обводкой.
  - **Состояние:** круг 8×8 цветом `--condition-<value>`. Шкала: отличное — зелёный, хорошее — салатовый, удовлетворительное — янтарный, плохое — красный.
  - **Освещение:** `Lightbulb` `weight="fill"` цветом `--lighting-on` (янтарный) и слово «Свет»; при `false` — `Lightbulb` `weight="regular"` цветом `--text-secondary` и слово «Без света»; при `null` чип не рендерится.
  - Каждый чип имеет `aria-label` с категорией («Состояние: хорошее»), потому что в видимом тексте категории нет.
  - Цвета задаются токенами для обеих тем; в тёмной теме — светлее, чтобы не тонуть в фоне. Контраст маркеров с фоном чипа ≥ 3:1 (не текст).
- `SportBadge` — круг цветом `--sport-<type>` с белой иконкой спорта, как у маркера на карте. В строке списка — 20 px перед названием, в карточке — внутри чипа спорта вместо цветной точки. Так одна и та же метка связывает маркер, строку и карточку.
- Блок `<dl>` фактов в карточке заменяется на `CourtFacts` `regular`.

### 20. Фильтры
- **Состояние** в `App`: `filters = { lit: boolean, goodCondition: boolean, surfaces: string[] }`. Чистые функции в `utils/filters.ts`:
  - `applyFilters(courts, filters)`;
  - `hasActiveFilters(filters)`;
  - `availableSurfaces(courts)`.
- **Конвейер:**
  - `courts → applyFilters` идёт и в карту, и в список; дальше для списка `sortCourts → filterCourts(query)`;
  - текстовый запрос сужает только список, как и раньше;
  - площадка, чья карточка сейчас открыта, всегда остаётся на карте, даже если не проходит фильтр. Иначе маркер исчезнет из-под открытой карточки.
- **`FilterBar`** — горизонтальный ряд без переноса, прокручивается пальцем, `role="group"` с `aria-label="Фильтры"`:
  - «Со светом» и «Хорошее состояние» (отличное + хорошее) — кнопки-переключатели с `aria-pressed`;
  - «Покрытие ▾» открывает поповер с чекбоксами только тех покрытий, что есть в данных. Изменения применяются сразу, кнопки «Применить» нет. Поповер закрывается по клику вне, Escape и повторному нажатию на чип;
  - подпись чипа покрытия: «Покрытие» → «Резина» → «Резина +1»;
  - в конце ряда появляется чип «Сбросить», когда что-то включено;
  - активный чип: фон `--accent`, текст `--text-on-accent`, слева иконка-галочка.
- **Размещение:**
  - мобильная карта — под плавающим полем поиска, непрозрачные чипы с `--shadow-1`, скрыт в режиме выбора точки;
  - мобильный экран поиска — под шапкой;
  - desktop — в шапке боковой панели под полем поиска.

  Состояние фильтров общее для всех мест.
- **Пустой результат:** если фильтры включены, список показывает «Ничего не найдено» и кнопку «Сбросить фильтры».
- **Анимации:**
  - смена фона и цвета чипа за `--dur-fast`;
  - поповер — `opacity` + `scale(0.96 → 1)` за `--dur-fast`.

  Маркеры при фильтрации не анимируются: на десятках меток это дорого на слабых телефонах.

## Risks / Trade-offs

- [Запрос геолокации при загрузке без контекста может раздражать или получить отказ] → Сохраняем текущее поведение (спека `frontend-mapping` уже его требует), но запрос один. При отказе всё работает без расстояний, а кнопка «Где я» позволяет повторить.
- [Загрузка всех площадок не масштабируется] → Порог пересмотра из решения 3. API с bbox сохранён.
- [Немодальная шторка + жесты карты: drag шторки может конфликтовать со скроллом содержимого] → Drag только за ручку и шапку (`touch-action: none` на них), содержимое скроллится нативно.
- [`margin` у `YMap` может не влиять на `setLocation` в текущей версии] → Фолбэк из решения 7. Проверить первым делом при реализации.
- [Детект Apple по UA неточен] → Ошибка безвредна: лишний или недостающий пункт меню, Google и Яндекс есть всегда.
- [`pushState` для слоёв усложняет историю вместе с `?court`] → Только слои пишут в историю, `?court` — только `replaceState`. Сценарий «назад» проверяется вручную на мобильной эмуляции.
- [Миниатюры 56×56 в списке грузят полноразмерные фото] → Ленивая загрузка и сжатие на клиенте при добавлении (решение 18). Если фото станет много — серверные превью отдельным изменением.
- [Ряд фильтров на мобильной карте занимает ~44 px сверху] → Чипы компактные, ряд прокручивается, карта под ним остаётся интерактивной. Ряд скрывается в режиме выбора точки.
- [Нет автотестов] → Каждая задача закрывается ручной проверкой по сценариям спеков в браузере (обе темы, 390×844 и 1280×800), плюс `npm run build` и `npm run lint` без ошибок. Ревью диффа — Opus.
