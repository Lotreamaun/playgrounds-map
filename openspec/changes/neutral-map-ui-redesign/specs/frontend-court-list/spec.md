## MODIFIED Requirements

### Requirement: View can switch between map and list
Список площадок SHALL открываться как результаты поиска поверх постоянно существующей карты:
- **desktop** — постоянно в боковой панели под полем поиска;
- **мобильный** — на полноэкранном экране поиска, который открывается тапом по полю поиска вверху экрана карты.

Закрытие экрана поиска на мобильном (кнопка «назад» экрана или выбор площадки) SHALL возвращать пользователя к карте в том же положении центра и зума, без перезагрузки страницы.

#### Scenario: Switch to list view
- **WHEN** пользователь на мобильном тапает по полю поиска на экране карты
- **THEN** открывается экран поиска с полем ввода в фокусе и списком площадок под ним

#### Scenario: Switch back to map view
- **WHEN** пользователь закрывает экран поиска кнопкой «назад» экрана
- **THEN** снова видна карта в том же положении центра и зума, что и до открытия поиска

#### Scenario: No full-screen page switch on mobile
- **WHEN** пользователь на мобильном открывает и закрывает экран поиска
- **THEN** это не навигация на другую страницу: адрес страницы не меняется, карта не перезагружается и не теряет положение

#### Scenario: No full-screen page switch on desktop
- **WHEN** пользователь работает на desktop и карточка площадки не открыта
- **THEN** список площадок виден в боковой панели под полем поиска, карта видна справа

### Requirement: List shows court details
Список SHALL отображать площадки строками; каждая строка соответствует одной площадке и показывает:
- слева миниатюру 56×56: фото площадки или заглушку с иконкой спорта, если фото нет (см. `frontend-court-ui` — «Court photo has a placeholder»);
- значок спорта перед названием и название;
- адрес (или заглушку «Адрес не указан»);
- ряд компактных чипов фактов «Покрытие · Состояние · Свет» (см. `frontend-court-ui` — «Court facts are shown as visual chips»);
- расстояние от пользователя, если его местоположение известно.

Строка SHALL быть целью касания не меньше 44 px по высоте. Значения SHALL не переноситься так, чтобы ломать раскладку строки.

#### Scenario: List row shows a court's address, surface, condition
- **WHEN** пользователь просматривает список площадок
- **THEN** каждая строка показывает миниатюру, значок спорта, название, адрес и чипы покрытия, состояния и освещения соответствующей площадки

#### Scenario: List row without a photo
- **WHEN** у площадки в списке нет фото
- **THEN** на месте миниатюры показана заглушка того же размера с иконкой спорта, и строки списка выровнены одинаково

#### Scenario: List row shows distance when location is known
- **WHEN** местоположение пользователя определено
- **THEN** каждая строка показывает расстояние до площадки («850 м», «2,4 км»)

#### Scenario: Court without an address in the list
- **WHEN** в списке находится площадка, у которой `address` не задан
- **THEN** строка отображает заглушку «Адрес не указан» без прекращения работы остальных строк

### Requirement: Courts sorted by distance from user's geolocation
Когда местоположение пользователя известно, список SHALL по умолчанию сортироваться по расстоянию от него, начиная с ближайшей площадки (расстояние по формуле Haversine). Отдельный переключатель сортировки SHALL отсутствовать. Когда местоположение неизвестно, список SHALL сортироваться по названию. Пока геолокация определяется, список SHALL уже показываться (по названию) и пересортировываться по расстоянию после ответа.

#### Scenario: Nearest courts appear first
- **WHEN** геолокация разрешена и местоположение пользователя определено
- **THEN** площадки отображаются в порядке возрастания расстояния от пользователя, без каких-либо действий с его стороны

#### Scenario: Nearest sort without geolocation
- **WHEN** геолокация недоступна или отклонена
- **THEN** список отображается в алфавитном порядке названий, без расстояний и без сообщения об ошибке

### Requirement: Clicking a list row focuses the court on the map
При выборе площадки в списке карта SHALL центрироваться на её координатах, маркер выделяться, а карточка открываться в контейнере платформы. На мобильном экран поиска при этом SHALL закрываться, чтобы пользователь видел карту с маркером и шторку карточки.

#### Scenario: Row click centers the court on the map
- **WHEN** пользователь выбирает строку площадки в списке
- **THEN** карта центрируется на координатах выбранной площадки, её маркер выделен, а карточка показана в шторке (мобильный) или в боковой панели (desktop)

## ADDED Requirements

### Requirement: Text search filters courts by name and address

Поле поиска SHALL фильтровать список площадок по вхождению введённого текста в название или адрес площадки, без учёта регистра и букв ё/е, мгновенно по мере ввода, без запросов к серверу. Сохраняется действующий порядок сортировки. Пустой запрос SHALL показывать все площадки. Поле SHALL иметь кнопку очистки, когда в нём есть текст.

#### Scenario: Filter by name
- **WHEN** пользователь вводит «ВАКЕ» при наличии площадок «Ваке-2» (адрес «Пекини 12») и «Мзиури» (адрес «Парк Мзиури»)
- **THEN** в списке остаётся только «Ваке-2»: совпадение по названию без учёта регистра

#### Scenario: Filter by address
- **WHEN** пользователь вводит часть адреса, например «чавчавадзе»
- **THEN** в списке остаются площадки, адрес которых содержит этот текст

#### Scenario: Clear search
- **WHEN** пользователь нажимает кнопку очистки поля поиска
- **THEN** поле очищается и список снова показывает все площадки

### Requirement: List communicates loading, empty, and error states

Список SHALL явно показывать состояние данных:
- при загрузке — индикатор загрузки (скелетоны строк);
- при пустом результате поиска — сообщение «Ничего не найдено» с подсказкой изменить запрос; если включены фильтры — ещё и кнопка «Сбросить фильтры»;
- при отсутствии площадок в базе — сообщение «Пока нет ни одной площадки» с действием добавить площадку;
- при ошибке загрузки — сообщение «Не удалось загрузить площадки» с кнопкой «Повторить», повторяющей запрос.

#### Scenario: Loading state
- **WHEN** данные площадок ещё загружаются
- **THEN** список показывает индикатор загрузки, а не пустую область

#### Scenario: Empty search result
- **WHEN** по введённому запросу не найдено ни одной площадки
- **THEN** список показывает «Ничего не найдено» и подсказку изменить запрос

#### Scenario: Load error with retry
- **WHEN** загрузка площадок завершилась ошибкой
- **THEN** список показывает «Не удалось загрузить площадки» и кнопку «Повторить»; нажатие повторяет загрузку

#### Scenario: Empty result with active filters
- **WHEN** включённые фильтры и запрос не оставили ни одной площадки
- **THEN** список показывает «Ничего не найдено» и кнопку «Сбросить фильтры»; её нажатие выключает все фильтры, а введённый запрос сохраняется

### Requirement: Courts can be filtered by lighting, condition and surface

Над списком SHALL быть ряд фильтров-чипов:
- «Со светом» — оставляет площадки с `has_lighting = true`;
- «Хорошее состояние» — оставляет площадки в состоянии «Отличное» или «Хорошее»;
- «Покрытие» — выбор одного или нескольких покрытий из тех, что есть в данных; остаются площадки с любым из выбранных покрытий.

Правила:
- Разные фильтры сочетаются через «И».
- Изменения применяются сразу, без кнопки «Применить».
- Фильтры действуют и на список, и на маркеры карты (см. `frontend-mapping` — «Filters apply to map markers»).
- Состояние фильтров общее для мобильной карты, экрана поиска и боковой панели desktop.
- Включённый фильтр визуально отличается от выключенного не только цветом: у него есть галочка. Screen reader объявляет его как нажатый (`aria-pressed`).
- Чип «Покрытие» показывает выбор: «Покрытие», «Резина», «Резина +1».
- Когда включён хотя бы один фильтр, в ряду есть чип «Сбросить».
- Ряд не переносится на вторую строку, а прокручивается по горизонтали.

#### Scenario: Lighting filter
- **WHEN** пользователь включает «Со светом»
- **THEN** в списке и на карте остаются только площадки с освещением, а чип выглядит включённым

#### Scenario: Condition filter
- **WHEN** пользователь включает «Хорошее состояние»
- **THEN** остаются только площадки в состоянии «Отличное» или «Хорошее»

#### Scenario: Surface filter with several values
- **WHEN** пользователь выбирает в «Покрытие» резину и дерево
- **THEN** остаются площадки с резиновым или деревянным покрытием, а чип показывает «Резина +1»

#### Scenario: Filters combine
- **WHEN** включены «Со светом» и покрытие «Резина»
- **THEN** остаются только площадки с освещением и резиновым покрытием

#### Scenario: Only existing surfaces offered
- **WHEN** пользователь открывает выбор покрытия
- **THEN** в нём перечислены только покрытия, которые есть хотя бы у одной площадки

#### Scenario: Reset filters
- **WHEN** пользователь нажимает «Сбросить»
- **THEN** все фильтры выключаются, и список с картой снова показывают все площадки
