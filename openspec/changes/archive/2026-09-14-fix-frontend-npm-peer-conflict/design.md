## Context

`frontend/package.json` фиксирует `typescript: "~6.0.2"` в корне проекта. `openapi-typescript@7.13.0` (текущая последняя версия на реестре — обновление пакета не решает проблему) объявляет `peerDependencies.typescript: "^5.x"`. При обычном `npm install` npm видит единственный экземпляр `typescript` в дереве (6.0.3) и не может удовлетворить peer openapi-typescript → `ERESOLVE`, установка прерывается. Подробности проблемы и её история — см. proposal.md.

`openapi-typescript` используется только как CLI-генератор типов (`npm run types:court`, разовый запуск против локального `openapi.json`) — он не импортируется рантайм-кодом и не участвует в `tsc -b`/`vite build`.

## Goals / Non-Goals

**Goals:**
- `npm install` в `frontend/` завершается успешно без ручных флагов (`--force`/`--legacy-peer-deps`) на любой машине и в CI.
- Версия `typescript` остаётся `~6.0.2` (без даунгрейда) — не тащить риски совместимости TS6-специфичных фич в остальном коде.
- Фикс точечный: подавляет именно этот конфликт, а не все peer-конфликты в проекте (чтобы будущие настоящие конфликты не проходили тихо).

**Non-Goals:**
- Не мигрируем `types:court` на другой генератор типов из OpenAPI.
- Не проверяем совместимость `openapi-typescript@7.13.0` с TS6 построчно — только что CLI успешно отрабатывает (см. задачи).

## Decisions

**Решение: `"overrides"` в `package.json`, принуждающий `openapi-typescript` использовать корневую версию `typescript`.**

```json
"overrides": {
  "openapi-typescript": {
    "typescript": "$typescript"
  }
}
```

`$typescript` — синтаксис npm overrides, ссылающийся на версию `typescript`, уже выбранную в корне проекта (не хардкодит дублирующуюся версию, которую пришлось бы поддерживать отдельно).

Проверено в изолированной песочнице (копия `package.json`/`package-lock.json`, тот же `node_modules`): с этим полем `npm install` без флагов ставит все 63 пакета, включая `@yandex/ymaps3-default-ui-theme`, и `npm ls typescript openapi-typescript` не показывает `invalid` — дерево валидно.

**Альтернативы:**

1. **`.npmrc` с `legacy-peer-deps=true` в `frontend/`.** Тоже устраняет ERESOLVE и не требует ручных флагов. Отклонено: глушит peer-проверку для *всех* зависимостей проекта, а не только для этой пары — будущий настоящий конфликт (например, несовместимая версия React) пройдёт молча вместо явной ошибки при `npm install`.
2. **Понизить `typescript` до `^5.x`.** Убирает конфликт «по-честному», но требует ревизии остального кода/конфига на TS6-специфичные фичи и понижает версию компилятора без функциональной причины — раньше в диалоге пользователь предпочёл не трогать `typescript` и обойти именно peer-проверку.
3. **Убрать `openapi-typescript` и генерировать типы вручную/другим способом.** Overkill для точечного конфликта версий; теряется удобство `npm run types:court`.

## Risks / Trade-offs

- **[Риск] `overrides` заставляет `openapi-typescript` работать с TS6, хотя пакет заявляет поддержку только TS5** → Митигация: задача в tasks.md — прогнать `npm run types:court` против локального бэкенда и убедиться, что генерация типов отрабатывает без ошибок перед тем, как считать изменение завершённым. Если CLI сломается на TS6 именно из-за типов (не просто предупреждение), придётся вернуться к альтернативе 2.
- **[Риск] `package-lock.json` меняется (пересборка дерева с overrides)** → Митигация: коммитить обновлённый `package-lock.json` вместе с `package.json`, не полагаться на локально пересобранный лок-файл без коммита.
- **[Trade-off] Overrides — менее очевидный механизм для будущих контрибьюторов, чем простой даунгрейд версии** → Митигация: комментарий/заметка в proposal.md с точной причиной (эта секция) остаётся в архиве openspec после архивации изменения.

## Migration Plan

1. Добавить `overrides` в `frontend/package.json`.
2. Пересобрать `frontend/package-lock.json` через `npm install` (без флагов) и закоммитить оба файла.
3. Проверить `npm run dev`, `npm run build`, `npm run types:court`.

Откат — тривиален: удалить поле `overrides` и старый `package-lock.json` из истории git (`git revert`), конфликт вернётся к состоянию до фикса.
