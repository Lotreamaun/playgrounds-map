## Context

Работаем только с фронтендом (React, Yandex Maps ymaps3, единый `index.css`). Сейчас `App.tsx` держит модель `view: 'map'|'list'` и полностью свопит экран; карточка площадки — привязанный к маркеру пузырь 220px, форма — плавающая панель 280px, переключатель и кнопка добавления — плавающие кнопки поверх карты. Мотивация и границы — в `proposal.md`. Требования (шторка, модалка, снятие свопа, локализация) — в delta specs этого change.

Ключевое ограничение: **дизайн-код (`:root`-токены `--accent`, `--shadow`, `color-scheme`, шрифты) не трогаем**. Мобильный слой строится из лейаут-CSS (медиа-запрос ≤767px, safe-area, стили компонентов) и изменений взаимодействия в компонентах.

## Goals / Non-Goals

**Goals:**
- Единый компонент нижней шторки (peek/expand/drag/dismiss + modal-вариант), используемый карточкой и списком.
- Форма добавления как полноэкранное модальное окно снизу.
- Убрать на мобилке своп `view: 'map'|'list'`; карта остаётся постоянной подложкой.
- FAB и компактный верхний бар поверх карты; тач-цели ≥44px; safe-area.
- Полная русификация видимых строк (в компонентах).

**Non-Goals:**
- Не менять дизайн-токены/тему в `:root`.
- Не трогать поведение на ≥768px (десктоп/планшет) — оно остаётся прежним.
- Не менять backend/API, не менять потоки данных и саму логику карты/геолокации.
- Не реализовывать поиск, фильтры и новые сущности за пределами перевода существующего UI в мобильный паттерн.

## Decisions

### D1. Модель состояния в `App.tsx`: шторка вместо свопа
Убираем `view: 'map' | 'list'`. Вводим состояние контейнера, который решает, что показано поверх карты:

```
sheet: { type: 'none' } | { type: 'card', court } | { type: 'list' }
addMode / addFormOpen: boolean   (полноэкранная модалка)
selectedCourt
```

- Карта (`MapView`) остаётся смонтированной всегда (или монтируется в мобильном брейкпоинте как единая подложка), а своп логики переезжает в выбор содержимого шторки/модалки.
- **Альтернатива (отклонена):** оставить `view` своп и отдельный экран списка. Проигрывает: ломает «карта как canvas», требует дублировать монтирование карты и теряет контекст.
- **Альтернатива (отклонена):** держать шторку глобально в `MapView`. Проигрывает: карточка/список/форма логически вне карты, усложняет состояние.

### D2. Единый `BottomSheet` с флагом `modal`
Карточка и список — «открытая шторка» (drag, peek/expand, закрытие жестом вниз или тапом по фону). Форма — `modal`-вариант: фиксируется на полную высоту `100dvh`, тянет клавиатуру/выбор фото, закрывается кнопкой отмены/отправкой.

- **Альтернатива (отклонена):** два отдельных компонента. Лишняя дупликация рендера подложки, фона-оверлея, safe-area и анимации.
- Замер/порог drag решается простой трансляцией `translateY` + порог по `offset`; на touch — `touchstart/touchmove/touchend` (без сторонних зависимостей, чтобы не тянуть библиотеку ради одного паттерна).

### D3. FAB + верхний бар поверх карты (только ≤767px)
- FAB вместо `add-court-button`: плавающая круглая кнопка снизу (над safe-area, зона большого пальца).
- Компактный верхний бар: locate/geo-подсказка и (ненавязчивая) точка входа в список. Точный набор кнопок добиваем в задаче — минимум: кнопка списка поверх шторки.
- Зум-контролы Яндекс.Карт оставляем в их нативном размещении, но на мобилке они компактнее за счёт их же темы; наш верхний бар не пересекается с ними по оси.

### D4. Медиа-запрос и safe-area
- Добавляем `@media (max-width: 767px)` в `index.css`, группируя мобильные правила. Явный единый брейкпоинт (не инвертировать десктоп-правила).
- Используем `env(safe-area-inset-*)` для FAB, шторки, верхнего бара и модалки (iPhone notch/home-indicator).
- `100dvh` (где доступно) вместо `100svh`/`100vh`, плюс запас для адресной строки браузера.
- **Альтернатива (отклонена):** CSS-фреймворк/utility. В проекте единственный `index.css`; добавлять Tailwind ради одного брейкпоинта — перегруз.

### D5. Локализация в компонентах
Все видимые строки (кнопки, label, placeholder, сообщения формы, карточки) переводим на русский прямо в JSX/модулях компонентов. Дизайн-токены и имена классов не затрагиваются. Отдельная i18n-прослойка не вводится (проект одноязычный MVP).

### D6. Карточка — контент внутри шторки
`CourtCard` остаётся компонентом контента, но рендерится внутри `BottomSheet` вместо привязанного к маркеру пузыря `court-marker__popup`. Логика фото-лайтбокса сохраняется. Маркер на карте при открытой карточке остаётся выделенным.

## Risks / Trade-offs

- **Gesture vs. карта (pixel-perfect)** → drag шторки должен поглощать вертикальные свайпы по своей площади; горизонтальные и касания по карте (в addMode) остаются на карте. Проверяем на реальном устройстве/эмуляторе.
- **Сложность жестов без библиотеки** → ограничиваем одним паттерном (translateY + порог), без параллакса/скорости; достаточно для MVP.
- **`100dvh` и адресная строка браузера** → используем `dvh` с фолбэком `vh`; тестируем iOS Safari.
- **Риск задеть десктоп** → все мобильные правила изолированы в `@media (max-width: 767px)`; десктоп-блоки не переписываем. Регрессию проверяем на ≥768px.
- **Коллизия верхнего бара и Яндекс.контролов** → позиционируем наш бар выше/вне области нативных zoom/locate, проверяем при мобильном зуме.

## Migration Plan

- Изменения аддитивные и изолированы медиа-запросом: на ≥768px поведение не меняется. Катать можно одним пр-ом без бэкапа.
- Порядок: компонент `BottomSheet` → перенос карточки → список в шторку → форма-модалка → `App.tsx` (снятие свопа) → FAB/верхний бар + CSS → русификация → проверка регрессии на ≥768px.
- Откат: переключение состояния свопа на прежнее и удаление медиа-запроса (паттерн гигиеничен, отдельных миграций данных нет).

## Open Questions

- Точный набор кнопок в верхнем баре (только «список», или ещё и locate-подсказка дублируется) — решено в задаче без изменения спеков и архитектуры.
- Пороговые значения высоты peek/expand — подбираются на реальном устройстве, не влияют на контракт.
