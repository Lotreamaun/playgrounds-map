## Context

`court_service.py` сохраняет фото в `data/photos/` и возвращает `photo_url = "/photos/{uuid}.jpg"`. Однако `main.py` не монтирует статический файловый сервер для этого пути — FastAPI не отдаёт файлы из `data/photos` по HTTP. Фронтенд получает 404 при попытке отобразить фото.

## Goals / Non-Goals

**Goals:**
- Файлы фото должны быть доступны по URL `/photos/{filename}` через GET
- Монтирование должно работать как в dev (uvicorn), так и в проде (Docker)

**Non-Goals:**
- Оптимизация хранения/размеров фото
- CDN или внешнее хранилище
- Аутентификация для доступа к фото (фото публичны)

## Decisions

### Использовать `StaticFiles` из Starlette

FastAPI построен на Starlette, который уже предоставляет `StaticFiles` — готовое решение для раздачи статики. Это стандартный подход, не требует новых зависимостей.

**Альтернативы рассмотрены:**
- Ручной роутер с `FileResponse` — избыточно, `StaticFiles` делает то же самое
- Nginx/CDN в проде — не исключает LocalFiles в dev, можно добавить позже

### Путь: `app.mount("/photos", StaticFiles(directory=...), name="photos")`

Монтирование на `/photos` совпадает с тем, что возвращает `court_service.py:114` (`/photos/{filename}`). Directory указывает на `data/photos`.

## Risks / Trade-offs

- **[R] Директория `data/photos` может не существовать при первом запуске** → `StaticFiles` создаёт 404 для несуществующих файлов, что корректно. Директория создаётся при первой загрузке фото через `court_service._save_photo`.
- **[R] Отсутствие очистки неиспользуемых фото** → Не решается этим change, но не критично для MVP.
