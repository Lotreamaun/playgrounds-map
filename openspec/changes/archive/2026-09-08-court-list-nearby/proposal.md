## Why

Сейчас площадки видны только как маркеры на карте — нельзя просмотреть их списком или найти ближайшие к себе. Для «народной карты» пользователи хотят быстро находить ближайшую к себе площадку (например, чтобы поиграть поблизости), а также видеть обзор всех площадок в виде списка, где удобнее сравнивать адреса, покрытие и состояние.

## What Changes

- Добавить переключатель режима отображения: **карта** / **список**
- В режиме списка показывать площадки в виде карточек-строк с адресом (поле `address` из change `court-address`), покрытием и состоянием
- Добавить «ближайшие площадки»: по геолокации пользователя отсортировать площадки по расстоянию (формула Haversine), показать ближайшие ближе к началу списка
- Клик по элементу списка центрирует карту на соответствующей площадке (при переключении в режим карты)
- Расширить API-клиент фронтенда, чтобы можно было запросить все площадки без bounding box (для заполнения списка)

## Capabilities

### New Capabilities
- `frontend-court-list`: режим отображения «список» и сортировка площадок по расстоянию от геолокации пользователя

### Modified Capabilities
- `frontend-mapping`: типизированный API-клиент получает возможность загружать площадки без bounding box (все площадки), чтобы заполнить список

## Impact

- **Frontend**: новый компонент списка (`CourtList`), переключатель вида в `App.tsx`, изменение `services/api.ts` (необязательный bbox в `getCourts`), координация с картой для центрирования по клику
- **No backend changes**: ближайшие площадки считаются на клиенте по уже загруженным данным (Haversine); `GET /courts` уже поддерживает запрос без bbox (все параметры необязательные)
- **Внешний API**: геолокация браузера (уже используется для центрирования карты)
- **Зависимость**: требуется поле `address` из change `court-address` для отображения адресов в списке
