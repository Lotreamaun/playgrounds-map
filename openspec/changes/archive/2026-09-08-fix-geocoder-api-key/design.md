## Context

See proposal.md — Why. Автоподстановка адреса при выборе координат работает через обратный геокодинг: `CourtForm` вызывает `reverseGeocode(lat, lng, apiKey)` из `frontend/src/services/yandexMaps.ts`. Функция `reverseGeocode` уже принимает ключ параметром и шлёт его в `geocode-maps.yandex.ru/v1`. Проблема в том, что `CourtForm` передаёт ключ Yandex Maps JS API (`VITE_YANDEX_MAPS_KEY`), который геокодер HTTP API отвергает (403 Invalid api key).

Геокодер и карта используют разные ключи Яндекса. Оба атрибута конфигурации читаются из `import.meta.env` (Vite, во фронтенде).

## Goals / Non-Goals

**Goals:**
- Разделить конфигурацию карты и геокодера на два независимых ключа.
- Заставить автоподстановку адреса работать с выделенным Geocoder API ключом.
- Сохранить коробочную деградацию: без ключа геокодера адрес оставляется незаполненным, форма продолжает сохранять площадку.

**Non-Goals:**
- Не менять логику обращения к геокодеру в `yandexMaps.ts` (функция уже параметризована ключом).
- Не трогать загрузку карты (`MapView`, `loadYandexMaps`) — она продолжает использовать Maps JS API ключ.

## Decisions

- **Ввести новый env `VITE_YANDEX_GEOCODER_KEY`** для геокодера. Загрузка карты остаётся на `VITE_YANDEX_MAPS_KEY`.
  - Rationale: Яндекс выдаёт ключи раздельно для JS Maps API и HTTP Geocoder API; они не взаимозаменяемы. Разделение устраняет корневую причину 403.
  - Alternative: использовать один ключ для всего — исключено, Яндексу нужен отдельный ключ.
- **Оставить `reverseGeocode` параметризованной по ключу** (не читать env внутри сервиса). `CourtForm` выбирает нужный ключ на верхнем уровне.
  - Rationale: минимальный дифф, сохраняет сервис чистым и тестируемым.
  - Alternative: читать `VITE_YANDEX_GEOCODER_KEY` внутри `reverseGeocode` — сложнее тестировать, смешивает уровни.

## Risks / Trade-offs

- У пользователя уже может быть закэширован неудачный результат в `addressCache` из-за 403. → Это пер-сессионный кэш только успешных/пустых результатов сброса; после изменения ключа адрес дозапросится при следующем клике по координатам.
- Если `VITE_YANDEX_GEOCODER_KEY` не задан, автоподстановка не работает, но форма корректно сохраняет площадку без адреса. → Приемлемая деградация, документируется в `.env.example`.

## Migration Plan

- Обновить `.env.example`, добавив `VITE_YANDEX_GEOCODER_KEY`.
- Пользователь добавляет реальное значение в локальный `.env` (вне git).
- Перезапуск dev-сервера Vite (env читается при старте).
