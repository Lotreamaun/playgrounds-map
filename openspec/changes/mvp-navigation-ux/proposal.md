## Why

Сейчас интерфейс — рабочий, но собранный из разрозненных паттернов: карточка площадки на desktop открывается в крошечном попапе рядом с маркером, тогда как на mobile — в полноценной шторке; выбор покрытия/состояния на форме и их отображение в карточке и списке показывают сырые английские значения enum (`asphalt`, `excellent`); встроенные элементы управления картой (zoom, геолокация) визуально не совпадают с акцентным цветом приложения и перекрываются с собственной кнопкой переключения режима; маркер площадки — безликая точка без указания вида спорта; появление большинства всплывающих элементов происходит без анимации. Чтобы показать сервис пользователям как MVP, интерфейс должен читаться как единый, локализованный продукт, а не как набор компонентов на разных стадиях готовности.

## What Changes

- Добавить словарь перевода значений `surface`/`condition` (например, `asphalt` → «Асфальт», `excellent` → «Отличное») и применить его в форме добавления, карточке площадки и списке — везде, где сейчас выводится сырое значение enum.
- Заменить desktop-попап карточки площадки у маркера на постоянную боковую панель слева (карта остаётся видимой справа), с той же ролью, что у мобильной bottom sheet: хостит карточку площадки, список площадок и форму добавления. Полноэкранное переключение «Карта/Список» на desktop убирается.
- Добавить явную кнопку закрытия (×) в боковой панели для карточки площадки.
- Заменить пустой кружок маркера на карте иконкой вида спорта (🏀 для баскетбола); форма и стили должны допускать добавление других видов спорта в будущем без переделки маркера.
- Добавить лёгкую анимацию масштаба для выбранного маркера (сейчас `isSelected` никак не меняет его вид).
- Добавить `transition` (transform/opacity) на все точки мгновенного появления интерфейса: боковая панель, hover строки списка, — по аналогии с уже анимированной bottom sheet; уважать `prefers-reduced-motion`.
- Переопределить тему встроенных элементов управления картой Яндекс.Карт (zoom, геолокация) под акцентный цвет приложения, чтобы карта не выглядела чужеродно на фоне остального UI.
- Развести позиционирование кнопок приложения (сейчас `view-toggle`) и нативных zoom/геолокация-контролов на desktop, которые сейчас перекрываются в одном углу.
- **Вне рамок этого изменения (осознанно отложено на post-MVP):** поисковая строка по адресу/названию, фильтры-чипы по покрытию/состоянию, мультиспортовые иконки помимо баскетбола.

## Capabilities

### New Capabilities
- `frontend-side-panel`: постоянная боковая панель на desktop — аналог мобильной bottom sheet, хостит карточку площадки, список площадок и форму добавления слева от карты, которая остаётся видимой и интерактивной справа.

### Modified Capabilities
- `frontend-court-ui`: локализация значений покрытия/состояния во всех местах отображения (форма, карточка, список); карточка площадки на desktop теперь открывается в `frontend-side-panel`, а не в попапе у маркера; карточка получает явную кнопку закрытия; выбранный маркер получает визуальное выделение (масштаб).
- `frontend-mapping`: маркер площадки отображает иконку вида спорта вместо пустой точки; встроенные элементы управления картой (zoom, геолокация) переопределены под акцентный цвет приложения; позиционирование контролов на desktop не перекрывается с элементами управления приложением.
- `frontend-court-list`: на desktop список площадок отображается в `frontend-side-panel` вместо полноэкранного переключения «Карта/Список».

## Impact

Только frontend, без изменений backend/API — значения `surface`/`condition`/`sport_type` в данных и контракте API не меняются, меняется только их отображение.

Затронутые файлы: `frontend/src/App.tsx` (замена полноэкранного переключения и floating-панелей на единую модель боковой панели/шторки), `frontend/src/components/CourtForm.tsx`, `frontend/src/components/CourtMarker.tsx`, `frontend/src/components/CourtList.tsx`, `frontend/src/components/MapView.tsx`, `frontend/src/index.css` (стили панели, тема карточных контролов Яндекс.Карт, transition, `prefers-reduced-motion`), новый модуль словаря переводов enum-значений.
