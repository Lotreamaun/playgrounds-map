## Context

Courtmap хранит площадки и описание в базе, фото выдаёт по HTTP. Публичная ссылка `?court=<id>` уже открывает конкретную карточку. Текущий API удаления защищён общим серверным токеном.

## Goals / Non-Goals

Открытие админки с телефона, проверка полномочий сервером, сохранение существующих ID и доставка уведомлений независимо от успешной публикации.

Обсуждения под площадками и команды редактирования внутри чата выходят за рамки изменения.

## Decisions

1. **Ссылки и доступ.** Telegram отправляет обычные HTTPS-ссылки на карту и закрытую админку. Ссылки не выдают полномочий. Для первого запуска использовать один серверный аккаунт администратора с настраиваемым паролем и защищённой cookie-сессией, проверкой CSRF для изменений и лимитом попыток входа. После входа адрес возврата обязан быть локальным. Это позволяет сохранить веб-форму для правок и не связывает права с доступом к сообщению бота.
2. **Данные и видимость.** Хранить статус скрытия на записи площадки и фильтровать публичную выдачу на сервере, включая прямой запрос по ID. Админский API позволяет убрать только описание или фото. При снятии фото с публикации закрывать выдачу исходного файла, а не только обнулять ссылку в карточке. Скрытие и восстановление использовать для целой карточки. Существующий DELETE остаётся для операторов с корректно настроенным токеном. Отключать его при отсутствующем или стандартном токене.
3. **Пользовательские обращения.** В первой версии предлагать правки структурированных характеристик, включая освещение, покрытие, состояние и крытую площадку. Пояснение необязательно. Использовать серверную валидацию полей и ограничение частоты отправки. Заявка хранит исходное и предлагаемое значения. При одобрении сравнивать исходное с актуальным в той же транзакции, где меняются площадка, статус заявки и журнал. В истории изменений хранить сведения, необходимые для разбора действий, без копий удалённого оскорбительного текста или фото.
4. **Доставка.** Сохранять задание на отправку в базе в одной транзакции с площадкой или обращением. Фоновый обработчик сразу подбирает новое задание и повторяет временные ошибки с задержкой. Уведомление содержит тип события и ссылку, без текста жалобы. При неопределённом результате отправки допустимо повторное уведомление. Отправка никогда не создаёт площадки или обращения.

## Risks / Trade-offs

- При публикации сразу вредный материал виден до реакции администратора. Уведомления, жалобы и отдельное удаление фото или описания сокращают время реакции.
- Недоступность Telegram задерживает уведомление. Администратор может открыть список площадок и очередь напрямую, а ошибки доставки доступны оператору.
- Добавление скрытия меняет поведение прямых ссылок. Восстановление возвращает доступ по исходному ID.

## Migration Plan

Сделать резервную копию базы и фото. Применить добавочную миграцию, в которой существующие площадки получают статус «Опубликована». Настроить учётные данные админки, бот и закрытый чат, проверить ссылки и доставку на тестовой площадке. Перед откатом приложения учесть, что старая версия игнорирует скрытие. Восстановление старой версии требует сохранить ограничения публичной выдачи или временно закрыть публичный доступ.
