## Why

Клик по индикатору кластера (и, как выяснилось при отладке, по встроенным zoom/геолокация-контролам Яндекс.Карт) должен зумить карту до разделения точек, но вместо этого карта почти мгновенно откатывается назад к стартовому состоянию (Тбилиси, zoom 12), и точки не распадаются. Причина — `frontend/src/components/MapView.tsx` передаёт `location={INITIAL_LOCATION}` в `<YMap>` как обычный React-проп, а не через `reactify.useDefault(...)`. По документации `@yandex/ymaps3-reactify`, без `useDefault` проп `location` переприменяется на каждом React-ре-рендере (`<YMap>` в этом смысле неконтролируемый компонент по дизайну), поэтому любой клик по React-кнопке, вызывающей `setLocation()` (наш клик по кластеру, встроенный zoom-control, locate-me-control), тут же откатывается обратно — а нативные жесты (колесо мыши, pinch), не проходящие через цикл ре-рендера, зум держат нормально. Ранее сделанная правка `zoom+3` в `handleClusterClick` не помогает, потому что чинит другую (уже не актуальную) проблему bounds-fit overshoot, а не эту.

## What Changes

- Экспортировать `reactify` (точнее, `reactify.useDefault`) из `frontend/src/services/yandexMaps.ts` вместе с остальными модулями Яндекс.Карт.
- В `frontend/src/components/MapView.tsx` обернуть `location` пропа `<YMap>` в `reactify.useDefault(INITIAL_LOCATION)`, чтобы этот проп задавал стартовую позицию один раз и не переприменялся на ре-рендерах, не мешая последующим императивным `setLocation()`-вызовам (клик по кластеру, зум-контрол, geolocation-контрол, центрирование на выбранной площадке).
- Убедиться, что уже реализованный пошаговый зум кластера (`zoom + 3` в `handleClusterClick`) действительно разделяет точки после устранения отката — если после фикса шага в 3 уровня недостаточно/избыточно, скорректировать.

### Modified Capabilities
- `frontend-mapping`: требование "Marker clustering" дополняется сценарием клика по кластеру, зумящего карту до разделения точек, без отката к стартовой позиции; требование "Locate-me control on the map" дополняется гарантией, что применённое через контрол положение карты не откатывается назад на следующем ре-рендере (тот же дефект воспроизведён и на встроенном zoom-контроле).

## Impact

- `frontend/src/services/yandexMaps.ts` — расширение экспортируемого набора модулей (`reactify`/`useDefault`).
- `frontend/src/components/MapView.tsx` — обёртка `location`-пропа `<YMap>`; сама логика `handleClusterClick` может не измениться или потребовать точечной корректировки шага зума.
- Бэкенд и API не затрагиваются.
