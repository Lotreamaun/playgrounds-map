## Why

При создании площадки через форму (`CourtForm`) нет возможности указать, есть ли на площадке освещение: поле `has_lighting` отправляется жёстко как `false` (`src/components/CourtForm.tsx:123`). После создания та же площадка в карточке (`CourtCard`) показывает факт «Освещение: Нет», и пользователь не мог повлиять на это при добавлении. Бэкенд, модель БД и типы API уже поддерживают `has_lighting` — меняется только frontend-форма.

## What Changes

- **`src/components/CourtForm.tsx`**: добавить переключатель «Есть освещение» (`role="switch"`, по образцу существующего «Крытая площадка»), состояние по умолчанию — выключено (сохраняет текущее поведение по дефолту «нет освещения»). При отправке формы передавать выбранное значение `has_lighting` вместо жёсткого `false`.
- Никаких изменений бэкенда, схемы БД, API-типов не требуется: `POST /courts` и модель `Court` уже принимают `has_lighting: boolean`.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `frontend-court-ui`: форма добавления площадки позволяет выбрать, есть ли освещение; значение сохраняется через `POST /courts` и отображается в карточке/списке как «Есть»/«Нет».

## Impact

- **Код (только frontend):** `src/components/CourtForm.tsx`.
- **Backend/API:** без изменений.
- **Документация:** openspec-изменение `frontend-court-lighting-on-create`.

## Non-goals
- Редактирование освещения существующей площадки после создания.
- Фильтр по освещению в списке (существующий фильтр `filters.lit` уже использует `has_lighting` из данных).
